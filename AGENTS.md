# UCLI contributor instructions

UCLI is experimental. Prioritize comfortable discovery, saved work, explicit
permissions and honest capability reporting. Unsupported, unavailable and unknown
are different states. A fixture is not provider admission.

Read the affected module's README, the relevant shared contract and
`CONTRIBUTING.md`. Keep changes narrow and use an isolated branch. Discuss shared
API, state-format, permission and account-binding changes before modifying their
consumers. Reuse the existing standard-library test and verification tools.

Preserve independent account/model/effort pins, durable command replay and unknown
outcome guards. A child process is not an OS sandbox. A timeout or local process
exit does not prove remote cancellation. Never widen permission or weaken an
admission check to obtain a passing test.

Use synthetic accounts and disposable homes. Do not start real sign-in, inference,
downloads or other external side effects unless the task explicitly authorizes
them. Never copy native credential stores, tokens, account identities, device
codes or private prompts into source, fixtures, receipts or public discussions.

Follow `docs/verification.md`. Report the actual commands, failures and skips,
including unexecuted provider or host paths. Keep raw local proof in ignored
`.build` directories; inspect and redact anything proposed for publication.
